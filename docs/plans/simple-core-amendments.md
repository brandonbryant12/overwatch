# Simple core amendments

These rules amend sections 4–11 and apply in numbered order. The companion interfaces document fixes the observable contract. The old build supplies parsers and comparison data only.

1. **Acquire the actual database.** Use a local filesystem and one canonical data file. Before schema inspection, set exclusive locking, enter WAL mode, acquire a physical write transaction and commit. Hold that connection through shutdown. Busy means exit before binding or announcing readiness. Opening a handle or setting the pragma alone proves nothing. A different SQLite binary can open a handle but its first query fails. SQLite cannot name the holder. Report the path and a verified live service address if available. Live status, doctor, trial and backup use HTTP. Offline status/backup/maintenance acquire ownership first. Never infer availability from a dead HTTP connection. A SQLite subprocess here got BUSY while the exclusive WAL owner was idle, then read successfully after close.
2. **Keep the database inode stable.** Renaming a fresh file over a locked pathname makes the old lock irrelevant. Restore offline into a fresh staging database using trusted current DDL, copy explicit plain-table columns as values, migrate known versions there, validate IDs, references, ranges, sequence watermarks, logical invariants and integrity. Use the already exclusively owned target connection to install the validated rows in one transaction, preserving the original on interruption. Rebuild derived indexes. Preserve the backup sequence and the next sequence, including after compaction. Never run SQL supplied by a backup. Reject future/foreign versions. A valid backup supplies data, never authority to contact an external system.
3. **Define what a source can distinguish.** A Kubernetes log key includes cluster/context, namespace, pod UID, container name and instance (container ID/restart generation), full UTC nanosecond timestamp, digest of original bytes and ordinal among *identical* entries at that timestamp in that instance. A new sibling or reordering distinct records cannot alter the key. Resolve current/previous container identity from metadata. Recheck identity around a log read. If it changes or cannot be established, discard the ambiguous read and record a gap. An observed truncated same-time multiplicity, rotation or missing previous instance gives lower-bound coverage. Identical records silently replaced by identical records are observationally indistinguishable. The exactness guarantee covers complete stable source windows with distinguishable multiplicities. Datadog uses the stable log ID scoped to account/source. Kubernetes event series count deltas of a UID's cumulative counter including the initial value. Keep that baseline beyond the overlap. A gauge sample has no log occurrence.
4. **Commit the whole slice.** Use event time, half-open bounds and a durable per-source watermark. Admit a late record at the overlap boundary, reject older records, prune only strictly older keys after inserting new keys in the same commit. Paginate to exhaustion or declare partial. Drop a cut tail. A failed read leaves its watermark alone. Count distinct new keys after replay, including within a page. At saturation persist a lower bound and one covered interval so replay cannot recount a discarded suffix. Insert at most 500 normal fingerprints per slice plus one stable overflow bucket for the rest. Previously observed late/missed records can be counted explicitly. Unknown omissions have null cardinality.
5. **Bound aggregate work.** The maxima multiply to ten million arrivals per minute. Five minutes at 32 bytes per key needs 1.6 GB before a single SQLite page, payload or index. Per-source maxima are admission limits under the disk budget. Stream with backpressure, use bounded batches or a protected temporary spool, keep memory independent of raw window bytes. Include WAL, staging and temporary files in free-space accounting. Refuse a slice before or during admission if reserve cannot be maintained, roll it back, leave its checkpoint unchanged and expose the pause. On resume, apply ordinary gap policy. At 1 GiB compact in a maintenance transaction, record the retained sequence floor and preserve incident totals, evidence in use and sequence allocation. Protected history alone exceeding the budget pauses growth. Append-only excludes explicit audited compaction.
6. **Make the boundary executable.** Type stripping erases a brand, a cast can fabricate one and SQL parameters also accept raw strings. The writer owns every statement and normalizes every external value recursively, including JSON keys, diagnostics, restore rows and generated search entries. Canonical identifiers are generated or digested before persistence. Apply the same policy before returning provider data to a model, printing errors or writing temporary spools. Secrets used as transport credentials stay out of observations. The testable guarantee is the documented family of redaction rules, not recognition of all possible secrets. Use structural checks on the writer and generated black-box sentinel tests together.
7. **Persist intent before dispatch.** Give each session and outbound message an Overwatch-chosen stable external ID. Read the peer's durable session, inbox and history before dispatch after uncertainty or restore. Reconcile remote filings with the restored job before starting new work. Retransmit only the same idempotent operation. Retire superseded attempts and deny their tools. If peer history expired or idempotency is unavailable, park for the owner. A snapshot cannot account for unrecorded work created on another timeline. Exactly-once applies to surviving intents with retained peer history.
8. **Bind evidence to a delivery.** Store the redacted bytes, source, immutable revision, run, attempt/session and an unpredictable run-scoped handle before returning bytes and handle together. The handle proves possession of the returned piece, not that a model understood it. Reuse only in the same continued session while active. A fresh retry gets a new namespace. Unknown, stale, mixed or empty citations reject the whole filing. Error replies may list previously returned handles only. Seeding a brief, a tool argument, an instruction, another finding and a model-supplied quote cannot mint evidence. A single valid filing closes the attempt atomically.
9. **Bind access independently of arguments.** Pin OpenCode 2.4.1 direct remote MCP mode (`codemode:false`). Require a local service credential plus `params._meta["ai.opencode/sessionID"]` and an active authorized mapping for the tool. MCP transport session IDs are unrelated. Configuration-defined agents deny all actions by default and allow named Overwatch tools. Verify the *effective* permission with a harmless call. A read-only empty cwd excludes accidental checkout context, but does not sandbox a process. Run model trials in an isolated data set with no owner actions or real external writes.
10. **Pin the object once.** Resolve the deployed revision to a commit. On failure, pin the current checkout commit explicitly as fallback or record no code. Preserve expected SHA, actual SHA and attribution in the brief, all code/history pieces and every filing across a continuation. Search/read/history resolve regular git blobs/tree entries only under that commit. Never read checkout contents or relabel fallback code as deployed. A fetch requires an approved configured remote; failure is a supported input.
11. **Make uncertainty observable.** Disabled-by-owner readings show the exclusion. Any expected missing, failed, capped, gap, suspended or stale reading prevents quiet. If none are expected, quiet is impossible. Health ages even during a hung poll. Restart deadlines use persisted wall deadlines clamped to the configured ceiling, elapsed live deadlines use a monotonic clock. One sign-in confirmation per cluster, permission confined to one read, slow probes recover, and one outage of a single source cannot imply the laptop is offline. Health and incident severity are distinct fields.
12. **Give the rubric a denominator.** Use the CLI, thresholds and clocks in the companion contract. M1 verifies the heartbeat wire, M2 disconnects it under a hung request in a browser. The owner runs doctor in launchd's actual environment and records two days including a sleep and VPN cycle, every overdue watcher and every health transition. The owner runs the configured GLM trial and saves version, scores and overlap. A scripted endpoint proves mechanics only. M2/M3 keyboard tasks use the seeded demo, search returns the seeded archived row within two seconds on the owner's laptop, and a copy reproduces the edited brief bytes. Count nonblank, noncomment service and page source lines including vendored executable code, exclude tests/docs. A colleague times a clean setup from clone to successful doctor with existing credentials. Publish timing, failures and any size exception before awarding A.

## For the owner

No amendment changes a fixed requirement or reverses a section 12 decision. Two stronger promises would need owner decisions and do not apply: exact identity through invisible Kubernetes log replacement needs a producer-side durable record ID, and guaranteed unattended progress after a peer forgets its history needs a durable idempotency guarantee from that peer. Neither is required for a truthful lower bound or a parked job.

## Assessor's verification

In the supplied OpenCode tree at `3ac14c0`, `packages/core/src/tool/mcp.ts:71` passes the invocation session, `mcp/index.ts:1099` and `mcp/pool.ts:332` carry it to the client, and `mcp/client.ts:942` writes the metadata on the outgoing call. `config/plugin/agent.ts`, `config/plugin/skill.ts` and the native `mcp.servers` config schema supply the integrations. `tool/plugin/skill.ts` checks permission at execution.

I ran the 2.4.1 native binary with an isolated home, a local HTTP MCP server, an OpenAI-compatible scripted streaming endpoint, one JSON-defined primary agent and one SKILL.md. The warm catalogs reported the agent, configured skill and connected remote server. Both simultaneous sessions called the remote tool with their own session IDs, peak simultaneous model requests was two, and the 0555 working directory remained empty. The model saw the named MCP tool and a built-in skill tool; both attempts to load the installed skill as the denied investigator returned `permission.rejected`. Startup catalogs can be empty before discovery completes. Doctor must wait for bounded discovery and verify the final configuration. This evidence covers the named version and scripted peer only.
